# ledger

A business platform sold as an API, starting with Dominican Republic electronic invoicing (e-CF). It is a modular
monolith: modules and country packs composed into a few apps that share one chassis and one PostgreSQL. The design
is [docs/superpowers/specs/2026-10-13-ledger-platform-v2-design.md](docs/superpowers/specs/2026-10-13-ledger-platform-v2-design.md).

Python 3.15 · uv workspace · strictly typed in two checkers · zero suppressions · 100 % branch coverage per package.

## Layout

| Path | What |
|---|---|
| `packages/` | `kernel` (the shared vocabulary, standard library only), `platform` (the chassis), `testing` (test tooling, dev-only) |
| `modules/` | Business modules, each in its own PostgreSQL schema and role: `identity` |
| `countries/` | Country packs: `do` (regime `do`, the e-CF channel) and its dev-only `do/testing` |
| `apps/` | The deployables: `api`, `worker`, `migrate`; they compose the installed modules and hold no business code |
| `contracts/` | Wire contracts (buf); protos arrive with the signer |
| `tools/devtools` | `ledger-devtools`: checks the manifests and generates what follows from them |
| `deploy/` | The image (`docker/ledger.Dockerfile`) and the local stack (`local/`) |

Every package has a `manifest.toml`, the source of truth for its dependencies, layers and generated files.

## Develop

You need [uv](https://docs.astral.sh/uv/) 0.13 or later (it installs CPython 3.15) and a running Docker: the tests
start a real PostgreSQL.

```bash
uv sync --all-packages   # every package of the workspace into .venv (the root itself depends on nothing)
uv run poe check         # the gate, as CI runs it
uv run poe fmt           # format and autofix
uv run poe sync          # after editing a manifest: rewrite what it implies, then commit the result
uv run poe               # every task
```

What `ledger-devtools sync` writes is never edited by hand: each `pyproject.toml` but the root's, `_manifest.py`,
`.importlinter` and `deploy/local/postgres/init.sql` (each headed `GENERATED by ledger-devtools sync`), and each
module's `openapi.json`.
`LEDGER_TEST_JOBS` caps how many packages test at once.

## The gate

`uv run poe check`: ruff format and ruff with every rule, no suppression comment anywhere, basedpyright (`all`)
and mypy `--strict`, import-linter, deptry, typos, buf, `ledger-devtools check` (manifests valid, generated files
current, image pins equal to `deploy/local/images.toml` and carrying digests, `.dockerignore` keeping
secrets out of the build context), vulture, and each package's tests with 100 % branch
coverage and warnings as errors. CI (`.github/workflows/ci.yml`) runs the same, then builds the image and starts
the local stack from it.

## Run locally

```bash
docker compose -f deploy/local/compose.yaml up -d --build --wait   # postgres, migrate, api, worker
docker compose -f deploy/local/compose.yaml down -v                 # stop and delete the data
```

| | Host address |
|---|---|
| api | `http://127.0.0.1:8100` (`LEDGER_API_PORT`) |
| worker (probes, metrics) | `http://127.0.0.1:8101` (`LEDGER_WORKER_PORT`) |
| PostgreSQL 18.6 | `127.0.0.1:5432` (`LEDGER_POSTGRES_PORT`), database `ledger`, login `ledger_app` |

Port 8000 is never used on the host. `/livez` and `/readyz` answer on both apps. To call the api with real
tokens, start the local Zitadel (compose profile `zitadel`): [deploy/local/zitadel/README.md](deploy/local/zitadel/README.md);
a stack started under its own project (`-p <name>`) gives its scripts the same `COMPOSE_PROJECT_NAME`.
An app run on the host takes `LEDGER_*` variables (see `deploy/local/compose.yaml`'s header) and sets
`LEDGER_HTTP_PORT=8101` for the worker (8100, the api's, is the default).
