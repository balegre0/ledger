# Working in this repository

For people and coding agents alike. The README says what the repository is and how to run it.

## Continuing the current work

Start with [docs/handoff/README.md](docs/handoff/README.md): the owner's rules, the process, the current state and the full backlog.

## Before changing anything

- Read the spec ([docs/superpowers/specs/2026-10-13-ledger-platform-v2-design.md](docs/superpowers/specs/2026-10-13-ledger-platform-v2-design.md))
  sections your change touches, and the ADRs in [docs/adr/](docs/adr/). When code and spec disagree, the spec
  wins: raise it, do not code around it.
- Manifests (`manifest.toml`) are the source of truth. A generated file starts with
  `GENERATED by ledger-devtools sync` (or is a module's `openapi.json`, or the root `pyproject.toml`'s block
  between its two marker lines): edit the manifest or the code, run
  `uv run poe sync`, commit what it wrote. Never edit a generated file by hand.

## The gate

- `uv run poe check` is green before every commit. Never hide an exit code (no `|| true`, no piping a failing
  command into something that succeeds) and never call a run green that you did not see finish green.
- Zero suppressions: no `# noqa`, `# type: ignore`, `# pyright:`/`# basedpyright:`, `# mypy:`, `# ruff:`,
  `# pragma: no cover`; no `Any`, no `cast`. When a checker objects, fix the code.
- Test first: write the failing test, see it fail for the right reason, then make it pass. Coverage is 100 %
  branch per package.

## Git

- One task, one commit (Conventional Commits). Commit locally; never push, amend, rebase or force anything
  unless the owner asks.
- `git mv` a file that survives a move, so its history follows it.

## The machine you run on

- Never kill processes by image name (`taskkill /IM`, `pkill -f`, `Stop-Process -Name`): stop only what you
  started, by its PID. Stop containers by id or with `docker compose -p <your project> down -v`; never stop
  containers you did not start.
- Host port 8000 belongs to another project: never bind it, call it or stop what listens on it. The api is on
  8100, the worker on 8101, the signer's probes on 8102 and the receiver on 8103 (`LEDGER_HTTP_PORT` for a host
  run).
- Secrets: never print `.env` files or their values (no `cat`, no `docker compose config` without `--quiet`, no
  `env | grep LEDGER`); edit them by variable name. Tax ids, tokens, request bodies and payloads never reach an
  error message, a log line or a span.
